# 4. 选型总结

## 1) 先判断问题类型

- 如果主要问题是“命中片段太碎、答案上下文不完整”，优先 **上下文增强**。
- 如果主要问题是“一次检索不够、需要多步推理”，优先 **流程增强**。
- 如果主要问题是“多轮会话、多文档协作、工具编排”，优先 **系统增强**。

## 1.5) 方法选择决策流程

```mermaid
flowchart TD
    start[识别主要失败类型] --> ctx{上下文不完整?}
    ctx -->|是| ctx_q{文档有层级结构?}
    ctx_q -->|有| stb[Small-to-Big / AutoMerging]
    ctx_q -->|无| sw[Sentence Window]
    ctx -->|否| flow{一次检索不够?}
    flow -->|是| flow_q{问题可拆解?}
    flow_q -->|可| rr[递归检索]
    flow_q -->|不可| flow_q2{检索质量不稳定?}
    flow_q2 -->|是| crag[Corrective RAG]
    flow_q2 -->|否| flow_q3{需要自动选择检索深度?}
    flow_q3 -->|是| ar[自适应检索]
    flow_q3 -->|否| ir[迭代检索]
    flow -->|否| sys{需要跨轮/跨文档/编排?}
    sys -->|跨轮| mem[Memory]
    sys -->|跨文档| mda[Multi-Doc Agent]
    sys -->|实体关系推理| graphrag[GraphRAG]
    sys -->|复杂编排| agent[Agentic RAG]
```

## 2) 方法选择速查表

| 方法 | 解决问题 | 主要改善指标 | 实现复杂度 | 延迟成本 | 推荐阶段 |
|---|---|---|---|---|---|
| Sentence Window | 命中句子缺少前后文 | 上下文完整性、答案覆盖率 | 低 | 低-中 | 优先尝试 |
| Small-to-Big | 小块命中但信息不全 | 召回精度 + 证据完整性 | 中 | 中 | 进阶常用 |
| AutoMerging | 多个子块分散命中 | 证据聚合质量、上下文连贯性 | 中-高 | 中 | 文档层级清晰时 |
| 迭代检索 | 首轮回答不完整 | 多轮补全率、最终覆盖率 | 中 | 中-高 | 需要逐步补全时 |
| 递归检索 | 复杂问题可分解 | 多跳任务完成度 | 中-高 | 高 | 多跳问答时 |
| 查询路由 | 多数据源或多索引 | 路由准确率、工具命中率 | 中 | 低-中 | 中大型系统 |
| Corrective RAG | 检索结果质量不稳定 | 上下文噪声率、事实性 | 中-高 | 中-高 | 质量优先场景 |
| Self-RAG | 需要动态控制检索 | 自反思决策质量、鲁棒性 | 高 | 高 | 高要求场景 |
| 记忆 | 需要跨轮连续性 | 多轮一致性、指代解析准确率 | 中 | 中 | 会话系统 |
| Multi-Document Agent | 跨文档协作与调度 | 跨源整合能力、任务完成率 | 高 | 高 | 复杂工程 |
| Agentic RAG | 需要规划-执行-反思闭环 | 复杂任务成功率、可恢复性 | 高 | 高 | 高复杂度场景 |
| 自适应检索 | 需要按复杂度选策略 | 策略匹配度、端到端效率 | 中 | 中 | 与查询路由配合 |
| GraphRAG | 需要实体关系推理 | 多跳准确率、全局覆盖度 | 高 | 高 | 知识密集场景 |

## 3) 三条落地原则

1. 先从低复杂度方法开始：`Sentence Window -> Small-to-Big -> 查询路由`。
2. 每引入一个增强策略，都要做前后对比评估（准确率、延迟、成本）。
3. 只有在基础方案稳定后，再引入记忆、Agent、自适应检索。

## 4) 推荐组合（2026 版）

1. **低风险增量组合**：`Sentence Window + 查询路由 + 轻量记忆`  
   目标：在可控复杂度下优先提升可用性与多轮体验。

2. **质量优先组合**：`Small-to-Big + Corrective RAG + 递归检索`  
   目标：提升复杂问题回答的完整性与事实稳定性。

3. **复杂任务组合**：`Multi-Document Agent + Agentic RAG + Self-RAG`  
   目标：处理多工具、多文档、长链路任务；必须配套可观测与回退策略。

4. **知识密集组合**：`GraphRAG + Corrective RAG + 自适应检索`
   目标：处理需要实体关系推理的复杂知识问答；按 query 复杂度动态调整策略。
## 5) 常见误区

- 误区 1：方法越高级，效果一定越好。  
  实际上高级方法通常同时增加延迟、成本和调参复杂度。

- 误区 2：把“query 改写”和“流程增强”混为一谈。  
  query 改写是输入优化，流程增强是系统决策优化。

- 误区 3：不做评估直接叠方法。  
  工程上应先定位瓶颈，再针对性增强。

- 误区 4：用 GraphRAG 替代向量检索。
  GraphRAG 擅长全局性和关系型问题，但对局部事实查询效率不如向量检索。两者互补，不是替代关系。
