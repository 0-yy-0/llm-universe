# 端到端 capstone：南瓜书问答闭环验收协议

这是一份收口协议，不是新的数据集、检索算法或统一 benchmark。它把前面各章已经展示的组件串起来，检查一次请求能否从问题走到有依据的回答，或在资料不足/无权限时安全拒答。

## 入口与范围

从[分开检查问题、资料与回答](分开检查问题、资料与回答.ipynb)开始，先确认问题、资料和回答的三层记录方式，再按本协议接入：

问题 →（可选）改写/路由 → 检索 →（可选）补查 → 后处理 → 回答 → 引用或拒答

只从当前 canonical 数据包中选择少量固定 regression 问题；本 capstone 使用的 evidence 必须来自经过固定流程审核的 canonical quote 记录。如果要覆盖多跳、资料不足或权限边界，分别选择对应的 canonical 案例。不要把 C2 的训练候选、未审核问题或 C6 的补充资料混入南瓜书闭环。

生成前只把原始问题和实际检索上下文交给回答模型，不把 `answerability`、`reference_claims`、`reference_answer`、`expected_pages` 或 `qrels` 作为提示词、路由或拒答特征。固定题统一调用回答模型，由模型仅依据 QUESTION+CONTEXT 返回 `answerable` 或 `insufficient`；生成完成后才加载 query metadata 和 qrels 做验收。

## 单题验收步骤

对每个选定问题，按下面顺序保存一条记录：

1. **问题**：保存 query_id、原始问题和必要范围；若做改写，另外保存改写后的检索词，并说明改写没有加入答案、页码或未授权事实。
2. **资料范围**：确认问题允许使用的文档和权限；资料不存在或当前用户无权访问时，记录拒答，不把相似页面交给回答端。
3. **检索**：保存检索方法、返回顺序、evidence_id、页码和实际候选原文。多轮或多跳时为每一轮记录触发原因、检索词和新增证据。
4. **后处理**：若使用排序、压缩、相邻页补查或去重，保存处理前后的候选集合、字符预算和被保留的原文；处理不能凭空产生证据。
5. **回答**：固定题统一只把实际候选原文交给真实回答模型；模型自行判断上下文是否足够，并返回严格 JSON。`answerable` 必须列出支持结论的 `evidence_id`，`insufficient` 必须返回空 `citations`，不能把 query 的评测标签传给模型。
6. **引用/拒答**：每条主要结论都能由一个或多个实际候选 evidence 支持，并且引用的 evidence_id/页码与原文相符；缺少支持时删去结论、继续检索或明确说明资料不足。

## 通过标准

一条 answerable 单题记录同时满足以下条件才算通过：

- 原始问题、实际检索输入、候选 evidence、回答和引用/拒答结果可以按顺序复查；
- 所有必要结论都有实际候选原文支持，引用没有错页、漏引或把参考答案当证据的情况；
- 多跳问题覆盖每个经固定审核流程确认的 essential evidence；资料不完整时，回答不会把局部片段扩写成完整结论；
- 只改变了某个组件时，至少复查一条原本正常的问题，确认没有明显退化；
- 运行环境缺少 canonical 数据、权限或必要模型时明确失败，不切换数据源、模型或伪造输出。

对资料不足或无权限问题，预期行为是模型返回 `insufficient` 且 `citations=[]`，而不是“回答得像真的”。随后用 canonical metadata/qrels 做拒答检查，并保留触发拒答的检索与上下文记录。

## 最小可复查记录

普通教学运行只需记录能解释该次结果的最小配置，例如：

- dataset manifest 版本或校验值；
- 采用的组件/方法、top_k 和上下文字符预算；
- 若确实改动了索引、模型或 Prompt，再记录相应版本；
- 逐题的 evidence 顺序、回答依据检查和最终判定。

只有在正式比较延迟、资源或线上运维时，才额外记录耗时、token、费用、错误率等运行指标；它们不是每次修改教程的必填项，也不能代替回答依据检查。

## 与核心 benchmark 的关系

核心 benchmark 仍由[比较改动前后](比较改动前后.ipynb)负责，并且只比较 BM25/CCH 检索排序。capstone 可以复用其中的 canonical 问题和 evidence 契约，但允许串入改写、补查、后处理和回答约束；它的结论只适用于实际验收的少量问题，不得改写成“所有专题方法都提升了统一指标”。
