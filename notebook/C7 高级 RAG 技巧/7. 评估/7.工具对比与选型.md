# 工具对比与选型

> 面向决策者的选型地图，帮助你在 10 分钟内完成技术选型。

## 一、主流工具对比

| 工具 | 类型 | 核心能力 | CI 集成 | 中文支持 | 适合场景 |
|------|------|---------|---------|---------|---------|
| **Ragas** | 开源指标库 | 组件级 RAG 指标最全，支持自定义指标 | 中等（需自行封装） | 好 | 离线评估、快速实验 |
| **DeepEval** | 开源测试框架 | pytest 风格，50+ 内置指标，一行代码定义测试 | 强（原生 pytest） | 好 | CI/CD 集成、回归测试 |
| **TruLens** | 开源评估框架 | RAG Triad 首创者，可编程反馈函数，内置仪表盘 | 中等 | 中等 | 实验对比、可视化分析 |
| **LangSmith** | 商业平台 | LangChain 生态深度集成，实验管理和追踪 | 强 | 好 | LangChain 技术栈用户 |
| **Langfuse** | 开源可观测 | 操作级评估，OpenTelemetry 集成，生产追踪 | 强 | 好 | 在线监控、生产环境追踪 |
| **Arize Phoenix** | 开源可观测 | UMAP 嵌入可视化，向量空间分析 | 中等 | 中等 | 调试分析、嵌入质量排查 |

## 二、选型建议

根据团队规模、技术栈和预算，按以下决策树选择：

```
你的场景是什么？
│
├─ 个人/小团队 + 快速验证
│  └─ → Ragas（最快上手，指标最全）
│
├─ 有 CI/CD 流程 + 需要回归测试
│  └─ → DeepEval（pytest 原生集成，CI 友好）
│
├─ LangChain 技术栈 + 需要实验管理
│  └─ → LangSmith（生态最深，体验最好）
│
├─ 需要生产环境监控 + 自托管
│  └─ → Langfuse（OpenTelemetry + 自托管）
│
├─ 需要全面评估 + 可视化仪表盘
│  └─ → TruLens（RAG Triad 首创者，内置仪表盘）
│
└─ 需要排查嵌入质量
   └─ → Arize Phoenix（UMAP 可视化）
```

### 组合推荐

实际项目中，通常需要组合使用：

| 阶段 | 推荐组合 | 原因 |
|------|---------|------|
| **开发期** | Ragas + DeepEval | Ragas 做指标实验，DeepEval 做回归测试 |
| **上线前** | DeepEval + LangSmith | DeepEval 做门禁，LangSmith 做实验管理 |
| **生产中** | Langfuse + Ragas | Langfuse 做在线监控，Ragas 做离线复盘 |

## 三、前沿展望

### Agentic RAG 评估

随着 RAG 系统从"检索-生成"演进到自主决策的 Agent 架构，传统指标面临新挑战：
- Agent 可能执行多轮检索，每轮的评估如何聚合？
- 工具调用的正确性如何评估？
- 自主决策的合理性如何度量？

### 多跳推理评估

多跳问答（需要综合多个文档片段才能回答）的评估需要 hop-aware 的逐步验证：
- 每一跳的检索是否正确？
- 推理链是否连贯？
- 最终答案是否正确？

### GraphRAG 评估

基于知识图谱的 RAG 在迭代检索中面临精度/召回的权衡：
- 图遍历深度如何影响答案质量？
- 子图选择的评估指标是什么？

这些前沿方向目前还没有统一的评估标准，值得持续关注。
