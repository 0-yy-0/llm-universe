# 建立和组织索引

这一章先讲向量库怎样同时保存向量、正文和资料属性，再处理片段离开原文后缺少背景、用户说法与原文不同，以及单一检索方法找不全的问题。

## 本章内容

1. [向量库和资料属性](向量库和资料属性.ipynb)：说明向量、正文、来源、页码和访问范围怎样一起保存，并区分 FAISS 这类近邻检索库、Chroma 这类轻量向量库、专用向量数据库、托管服务和兼具全文/向量检索的搜索引擎。
2. [给片段补充章节标题](给片段补充章节标题.ipynb)：把真实章名放到片段前面，再比较检索结果。
3. [给片段补充所属上下文](给片段补充所属上下文.ipynb)：为短片段生成有原文依据的背景，再比较原文与增强字段的检索结果。Notebook 同时保留生成文字、校验说明和实际检索字段。
4. [给片段补充检索说法](给片段补充检索说法.ipynb)：原文写法固定时，为片段补上读者可能使用的说法。
5. [结合关键词和向量检索](结合关键词和向量检索.ipynb)：比较关键词检索、向量检索和两者合并，看看合并在什么情况下有用。
6. [比较索引增强方法](比较索引增强方法.ipynb)：可选的 C3 横向实验，在同一批南瓜书问题、同一小候选语料、同一 `top_k` 和相同检索字段字符预算下，比较原文、可靠章节标题（CCH）、GLM 生成问题（Document Augmentation）与 GLM 背景（Contextual Retrieval）。增强字段只用于索引，命中后按稳定片段 ID 映回原文；回答映回只核查来源，不组装或比较回答上下文。Notebook 保存真实模型输出、结构校验以及改善、不变和退化。

## 结果与限制

补充所属上下文的实验从两道问题预筛出 21 个候选片段，调用 `glm-4-flash` 生成背景，再按原文、页类型、目录特征和长度检查；校验不使用预期页、参考答案或目标排名。保存的 21/21 个片段都有真实原始输出（`fresh_api_run`）：主案例正确页由第 3 名升到第 1，复查题由第 1 降到第 2。它只说明这组候选的变化，背景文字用于检索，回答仍需引用原文。

给片段补背景和补充检索说法处理不同缺口；关键词与向量合并也可能不变或退化，相关结果都保留在对应 Notebook 中。

横向比较页是可选实验，用来观察几种字段在同一设置下的取舍；现有专题页仍各自承担单机制学习，包括 CCH、Document Augmentation 和 Contextual Retrieval 的原理、提示词与边界。横向实验只有 3 道问题和 9 页候选语料，不能替代完整评测，也不能把局部结果外推为全库收益。

运行前按[教程首页](../README.md#运行准备)在 C7 根目录准备 `requirements-c7.txt` 与指定模型缓存；生成型实验还需要仓库根目录 `.env` 中的 `ZHIPUAI_API_KEY`。
