# 维护说明

本页只供维护者使用，不是教程入口。教程正文、Notebook 代码和已保存的真实输出是当前项目的说明；本页只记录如何检查它们。

## 日常检查

在 C7 根目录使用 Python 3.10 环境：

```bash
python scripts/prepare_dataset.py --check
python scripts/check_dataset.py --dataset data/dataset
python scripts/check_tutorial.py
python ../../scripts/check_c7_release_snapshot.py
pytest -q ../../tests/c7
```

有意修改 canonical JSON/JSONL 后先运行不带 `--check` 的 `prepare_dataset.py`：它只针对明确的当前数据包，在隔离副本验证通过后刷新 manifest 的数量与 SHA-256，不会从 Git 或其他文件恢复数据。`check_dataset.py` 检查 manifest、字段、引用、重复 ID、空训练问题、训练正例水印和 split 泄漏。`check_tutorial.py` 检查 Markdown/Notebook 链接、Notebook JSON 与保存的执行输出、PDF/向量库资产清单、多来源当前文件和三项完整实验入口；另外只在本地重跑不调用 API 的 BM25/CCH 核心 benchmark，并比较当前报告与比较 Notebook 的已保存 JSON。`check_c7_release_snapshot.py` 是只读的发布纳入检查，不会执行 `git add`、提交或删除文件。

修改了 Notebook 代码后，使用仓库配置的 `llm-universe-c7` kernel 从 C7 根执行受影响的 Notebook。提交前确认代码单元都有执行计数、没有保存的 error output，结构化审计输出仍在，且输出与正文声称的输入范围一致。

## 当前资料边界

南瓜书 PDF 和随附向量库是核心单文档路径；PDF 来源、许可、SHA-256、向量维度、collection 与记录数以 `data/asset_manifest.json` 为准。所有核心问题、原文证据、qrels、会话和 split 只从 `data/dataset/` 读取，并通过 `common/dataset.py` 校验。不要重新引入第二份问题 JSON、派生索引或未登记的训练/评估文件。

多轮多来源助手只读取 manifest 登记的三个当前仓库文件：`data/dataset/manifest.json`、`2. 数据处理/README.md` 和 `7. 评估/README.md`。每份资料都登记 source_id、来源类型、用途和 SHA-256；它们用于多源合并、会话追问、评估范围比较与资料不足演示。冲突分支只使用 Notebook 内存中的最小 fixture，不伪装成当前项目事实，也不写入真实会话历史。

## 模型和输出

需要生成内容的 Notebook 只使用 `.env` 中的 `ZHIPUAI_API_KEY`，固定调用 `glm-4-flash`。缺少依赖、资料、密钥或 API 响应时直接报错；禁止备用密钥、备用模型、静默跳过、硬编码回答和伪造执行结果。模型原始输出、来源选择、改写问题、检索证据和必要的结构化检查应随 Notebook 保存。

正式对比按需保留足以解释差异的最小配置：固定问题批次与数据/evidence 版本（或 manifest hash）、检索的 `top_k`/字符预算，以及生成实验实际使用的模型和 Prompt 版本；同时保存改动前后输出与必要证据覆盖。没有测量的数据写“未测量”，不要求普通教学运行额外记录时间、revision、token 或费用。一次问题上的改善不代表换资料、模型、Prompt 或问题后仍然有效。向量微调、索引增强和多轮多来源三个完整可选实验与主线 benchmark 共享契约，但各自的资料范围和结论必须分开。

## 资产变更

新增或替换 PDF、向量库、canonical JSONL、多来源当前文件或完整实验 Notebook 时，先更新对应 manifest，再运行两套 checker 和受影响 Notebook。当前学生正文只保留本项目可复核的最终资料、代码、输出和边界说明；版本追溯交给 Git。

## 发布 Git 白名单

最终快照至少应包含以下范围：

- 根入口：`README.md`、`docs/README.md`，以及只读检查脚本 `scripts/check_c7_release_snapshot.py`；
- C7 教程：`notebook/C7 高级 RAG 技巧/` 下的 README、维护说明、章节 Markdown/Notebook、`common/`、`scripts/`、canonical `data/dataset/`，以及 asset manifest 声明的多来源文件和完整实验 Notebook；
- 测试：`tests/c7/`；
- 成套向量库：`data/asset_manifest.json` 中 `vector_store.required_files` 列出的 `chroma.sqlite3` 和四个向量索引二进制文件，不能只纳入其中一部分。

`.DS_Store`、`.codex*`、`.luna*`、`.tmp*`/`tmp`/`temp`、`.cache`、`.pytest_cache`、`__pycache__`、`.ipynb_checkpoints`、`*.pyc`/`*.pyo` 都是本机或临时文件，不得纳入。检查脚本只报告路径；它不会替你执行 `git add`、提交或删除文件。工作区存在并行任务的临时目录时，以脚本的 `ambient_not_in_release_scope` 报告为准。
