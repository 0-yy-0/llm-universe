# 决定要不要查、怎样查

这一章讨论检索前筛选、改写问题、同一意图的 MultiQuery、拆成子问题、先查一般原理、先写一个可能的答案再检索，以及什么时候应该继续查找。

## 改写、MultiQuery 与拆题

三者都可以放在检索前，但边界不同：单次 query rewrite 把一个问题改成一个更清楚的查询，适合口语、省略、指代或术语不一致；MultiQuery 为同一意图生成多个不同措辞，适合同义词、词序或表达视角不一致，仍然回答同一个问题；decomposition 则把确实包含多个独立目标的复杂问题拆成子问题，每个子问题都需要自己的证据。MultiQuery 的代价是额外检索、重复和噪声，拆题的额外风险是丢失条件或漏掉子目标；两者都不能承诺普遍提升。

MultiQuery 必须把原 query 和生成的 variants 一起检索，再按稳定文档 ID 去重合并，同时保留每条查询的命中来源。拆题则应按子目标记录覆盖，最后检查每个子目标，而不是把多个表达误当成多个问题。完整的单次真实 MultiQuery 调用和逐 variant 命中记录见[改写检索问题](改写检索问题.ipynb)；缺少密钥、依赖、响应或结构校验失败时直接报错。

## 本章内容

1. [从问题中提取筛选条件](从问题中提取筛选条件.ipynb)：把明确的资料范围和主题条件与正文检索词分开。
2. [检索前过滤无权访问的资料](检索前过滤无权访问的资料.ipynb)：根据当前用户的权限缩小可检索范围。
3. [改写检索问题](改写检索问题.ipynb)：比较直接改写、同一意图的 MultiQuery、拆成子问题和先查一般原理。
4. [先写一个可能的答案再检索](先写一个可能的答案再检索.ipynb)：真实调用 `glm-4-flash` 生成一段只含方法名和检索概念的假设文字，再用随附向量库检索。当前保存输出中，基尼指数问题的第 49 页由第 2 条升到第 1 条，交叉验证复查题的排名和覆盖保持不变；假设文字不能直接当答案。
5. [判断是否需要继续检索](判断是否需要继续检索.ipynb)：比较已有资料足够时停止和缺内容时继续查找。
6. [让检索器适应回答模型](让检索器适应回答模型.ipynb)：训练型扩展阅读，介绍 PRCA 和 REPLUG 要优化什么。本页只保留方法原理和一个分布对齐的计算例子，没有训练这两种方法，也不把它写成效果比较。实际的向量模型微调已经在 [C2 微调 Notebook](../2.%20数据处理/什么时候需要微调向量模型.ipynb) 中完成，不能把 C2 的真实训练与本页的研究型示意混为一谈。

这些方法不是一条流程中必须全部开启的步骤。先确认问题是筛选条件、表达不匹配、内容缺失还是训练目标不一致，再选对应方法。

## 基础路径与训练型扩展

基础路径是前 5 个 Notebook：先处理筛选、权限、改写、拆题和继续检索，再把结果交给后处理与回答约束。只有当检索器需要适应回答模型的偏好、并且确实有输入—答案或上下文标注时，才阅读第 6 个 Notebook；PRCA/REPLUG 需要独立训练、资源和评估，不能作为基础 RAG 的必做步骤。

## 实践任务：为一个多条件问题选择一次检索动作

从自己的资料中选一个同时带有范围、术语或多个目标的问题，保留原 query。只选择一种动作：单次 rewrite、同一意图的 MultiQuery 或 decomposition；记录生成的 query/variants、各自命中和按稳定文档 ID 去重后的结果。若问题其实只有一个目标，不要为了展示流程强行拆题。

### 自检标准

- 每个改写或子问题都保留原始范围和目标；MultiQuery 是同一意图的不同说法，decomposition 才有多个独立子目标。
- 合并结果中没有重复稳定 ID，且每条命中仍能回到原文 `source/page/quote`；查询失败或结构校验失败时直接记录失败，不使用备用 query。
- 用固定 `top_k` 与至少一个未改写对照，报告目标证据排名、增加的检索次数和是否漏掉子目标，不能只报告答案变好。
