# 高级 RAG 技巧

## 学完能做什么

完成本教程后，你可以从一条答错的问题出发，判断问题出在资料、检索还是回答；选择合适的分块、索引和检索方法；处理遗漏证据、追问和多个资料来源；最后用固定问题复查改动，并完成带引用或资料不足声明的问答流程。

主线使用固定版本的《南瓜书》。你不必一次开启所有高级方法：先找到具体缺口，再做一个改动，检查目标问题是否改善、原本正常的问题是否退化。Notebook 保存了实际输入、输出和结果范围，可以先阅读，再选择需要重跑的实验。

## 运行准备

统一使用 Python 3.10 和 `llm-universe-c7` kernel。下面从仓库根目录进入 C7；之后本教程中的 `data/...`、`scripts/...` 和依赖路径都相对于这个 C7 根目录，章节 README 不需要再次 `cd`：

```bash
cd "notebook/C7 高级 RAG 技巧"
python -m pip install -r requirements-c7.txt
python -m ipykernel install --user --name llm-universe-c7 --display-name "Python 3.10 (llm-universe-c7)"
python scripts/check_dataset.py --dataset data/dataset
python scripts/check_tutorial.py
```

在 Jupyter 中选择 `Python 3.10 (llm-universe-c7)`。用 CLI 从头执行时，显式加上 `--ExecutePreprocessor.kernel_name=llm-universe-c7`，避免调用到其他 Python 环境。本章 40 本 Notebook 的 kernelspec 已统一为该名称。

只阅读已保存的 Notebook 输出不需要调用 API。本地实验使用随附 PDF、向量库或规则；需要新问题向量或重排的页面还需按章节说明提前准备固定模型缓存。模型准备完成后，相关实验从本地缓存加载。

需要生成文字的页面从仓库根目录 `.env` 读取 `ZHIPUAI_API_KEY`，固定调用 `glm-4-flash`。缺少依赖、模型、资料或必要配置时会直接报错；先按报错补齐运行条件，再重跑该页。C2 的 BGE 缓存准备见[数据处理](2.%20数据处理/README.md)，C5 的重排模型见[生成阶段](5.%20生成阶段/README.md)，CRAG 资源见[处理信息缺口](6.%20处理信息缺口/README.md)。

## 可选实验

以下三个实验保留完整代码与实际结果，学完相关章节后可独立运行。

1. [数据构建与向量模型微调](2.%20数据处理/什么时候需要微调向量模型.ipynb)：用 query→原文 evidence 训练 BGE，在 dev 上选择配置，保存并重载模型、重新编码语料，最后比较 frozen test。当前 34 道冻结测试题中 9 道排名改善、3 道退化、22 道不变。
2. [索引增强同题比较](3.%20索引阶段/比较索引增强方法.ipynb)：在同一批 3 题、9 页候选语料、同一 `top_k` 和检索字段预算下比较原文、章节标题、生成问法与生成背景。CCH 在“算法有没有绝对更好”题上把必要页首条排名从 3 提到 2，Document Augmentation 在“集成多个弱学习器”题上从 2 提到 1；增强字段只用于检索，命中后映回原文。
3. [多轮多来源助手](6.%20处理信息缺口/构建多轮多来源助手.ipynb)：直接读取数据 manifest、数据处理 README、评估 README 三份当前文件，串起追问补全、各源检索、证据合并和引用绑定。新会话的完整首问正常运行，缺少可用历史的歧义追问先澄清。

阅读实验结果时，分清“方法是否适合目标题”和“是否影响其他问题”。前者在 C3 的局部适配实验中观察；后者在[比较改动前后](7.%20评估/比较改动前后.ipynb)中，用固定 6 题比较 BM25/CCH。当前回归结果保留 2 题退化。两者的问题、证据池和预算并不完全相同，检索排名变化也不能直接说明回答质量；完整范围与逐题结果见[评估说明](7.%20评估/README.md)。

## 数据与维护

`data/dataset/` 是统一的数据包（代码中称为 canonical）：问题、证据、相关性标注 qrels 和会话都从这里加载，由 `common/dataset.py` 校验。PDF、向量库的来源、许可和校验信息见[数据说明](data/README.md)，数据记录入口见[manifest](data/dataset/manifest.json)。

微调题集保留 163 条 query→evidence pair，分为 101 train、28 dev、34 frozen test，覆盖 55、14、17 个互不重叠的 PDF 页面。问法由 `glm-4-flash` 生成和初审，再由同一 `glm-4-flash` 发起另一次独立语义审核请求；110 条二次剔除记录及理由单独留档，保留记录均为 `human_verified=false`。这是有限的合成问法分布，相关结果不能外推为自然用户问题的覆盖情况，也不能把模型审核称为人工核验。

修改资料或代码时，按[维护说明](docs/维护说明.md)更新对应清单并重跑受影响的 Notebook。多来源助手引用当前 README 的原文，修改这两份来源后也要刷新其保存输出。维护者准备 Git 快照时，回到仓库根目录执行只读检查 `python scripts/check_c7_release_snapshot.py`；它只报告纳入范围。

## 贯穿式实践任务

完成七章后，选自己的一份短资料和一个真实问题，沿“第 1 章诊断 → 第 2 章分块 → 第 4 章检索 → 第 7 章评估”做一次小实践。只改一个主要变量，保留原问题、原文证据、top-k、上下文预算和改动前后结果；不要把自己的资料写入 canonical 数据包，也不要把一次成功写成全库收益。

**自检标准：** 结果记录同时包含 `source/page/quote`、改动前后首条相关排名或 Recall@k、上下文字符/token 预算和一条退化检查；回答中的每条关键结论都能回到原文，资料不足时明确拒答；若无法填写其中任一项，应回到第 7 章补齐评估记录，而不是继续叠加技巧。
