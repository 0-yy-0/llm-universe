# 检索后处理与回答约束

本章把候选资料整理成回答所需的上下文，再核对回答和引用。四个专题集中在[排序、压缩与回答](排序、压缩与回答.ipynb)，按下面顺序阅读即可。

| 遇到的问题 | 处理方法 | 检查什么 |
|---|---|---|
| 正确片段已在候选中，但排得太后 | 重新排序 | 候选集合不变时，必要片段是否进入前列 |
| 候选太长，必要结论可能被截断 | 上下文压缩 | 同一字符预算内是否保留完整原文依据 |
| 回答写出了结论，但来源不清楚 | 来源标注 | 每条结论与实际原文、页码是否对应 |
| 候选没有支持所需结论 | 资料不足与拒答 | 是否明确说明缺口，避免根据相似片段猜测 |

## 实验与结果范围

前面的排序教学例子使用本地 BM25/关键词重排，展示轻量排序如何改变同一批候选的顺序。来源标注部分比较同一段固定回答在添加页码前后的差别，并检查错页、漏引和没有依据的结论；这部分没有调用回答模型，因此不能据此计算生成质量。

四种处理可以独立采用。压缩必须保留支持结论的原文，来源标注仍需逐条核对；若要接入真实生成器，在整理上下文后生成，再保存实际回答、引用和资料不足结果。完整流程可继续看[端到端验收](../7.%20评估/端到端验收.ipynb)。

## 可选：真实 Cross-Encoder 比较

Notebook 末尾使用 `BAAI/bge-reranker-large` 与 LangChain `CrossEncoderReranker`，对一个 SVM 问题的第一阶段 6 条候选重新打分。它与轻量基线使用同一问题、候选集合和 `top_k`，保存分数、必要页排名和改善/不变/退化结果；单题结果只适用于这次对照。

先按[教程首页的运行准备](../README.md#运行准备)进入 C7 根目录并安装 `requirements-c7.txt`。该文件已固定本页使用的 `modelscope==1.33.0`、`langchain==0.3.27`、`langchain-community==0.3.30` 和 `langchain-core==0.3.76`，无需再安装另一套章节依赖。然后在同一 C7 根目录、网络可用时准备一次模型缓存：

```bash
python -c "from modelscope import snapshot_download; print(snapshot_download('BAAI/bge-reranker-large'))"
```

Notebook 使用 `local_files_only=True` 读取缓存。依赖或权重缺失时先完成准备；跨编码器的排名、延迟和成本仍需在自己的开发集上比较。

完成本章后进入[处理信息缺口](../6.%20处理信息缺口/README.md)或[评估](../7.%20评估/README.md)。

## 实践任务：在固定候选上完成一次有依据的回答

从自己的检索器固定取回 4—6 条候选，只选择排序、压缩或来源标注中的一个主要改动。把必要原文放入一个明确的字符/token 预算，再生成一段回答；另准备一个候选不足的问题，按“资料不足”规则处理，不用相似片段补猜。

### 自检标准

- 改动前后候选集合、问题和预算相同，记录必要片段首条排名及最终上下文长度。
- 每条关键结论都绑定实际原文和页码；压缩不能删掉支撑条件，排序不能偷偷增加候选。
- 候选不足时回答明确说明缺口并停止猜测；若引用错页、超预算或出现无依据结论，实践不通过。
