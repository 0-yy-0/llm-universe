# 增强阶段章节优化设计方案

## 背景

C7 第六章"增强阶段"已有重构版内容，但存在以下问题：
- 旧版文件与重构版并存，目录混乱
- 先导 notebook 与各章节的 baseline 内容重复
- 三个 notebook 的代码与文字比例失衡（代码多、讲解少）
- 方法之间缺少过渡段落和结果分析
- `3. 系统增强` 中 Agentic RAG 篇幅不足
- 各 notebook 结构不统一（部分有学习检查点，部分没有）

## 设计决策

| 决策项 | 结论 |
|---|---|
| 旧版文件 | 删除 |
| 先导 notebook | 删除，核心内容融入 readme |
| 教学风格 | Case 驱动（章节级 baseline + 方法逐个修复对比） |
| Agentic RAG | 在系统增强内扩充为压轴，不单独成章 |
| 系统增强方法顺序 | Memory → Multi-Doc Agent → GraphRAG → Agentic RAG |

## 二、readme.md

重写为章节入口页，吸收先导核心内容：

```markdown
# 第六章：增强阶段

## 基础 RAG 的三个隐含假设
（3句话：一次检索就够、命中就能答、问题独立存在）

## 当假设不成立时
（1段话串联三层增强的逻辑）

## 方法地图
（mermaid 流程图，从先导搬入并修复闭合问题）

## 本章内容
1. 上下文增强.ipynb
2. 流程增强.ipynb
3. 系统增强.ipynb
4. 选型总结.md
```

不保留"与前几章的边界"和"本章新增方法（2026）"——前者由各 notebook 内部按需提及，后者是 changelog 不是教学内容。

## 三、统一 Notebook 模板

```
章节标题 + 一句话定位
本章要解决什么（1-2段文字）
统一实验设置（代码）
Baseline 失败 demo（代码 → 看到坏输出）
失败分析（文字，指出根源，引出方法）

[方法N] × 重复
  ├── 过渡引入（文字）
  ├── 思路 + 流程（文字/表格/图）
  ├── 核心代码
  ├── vs Baseline 对比 + 结果分析（代码+文字）
  ├── 适用边界（文字）
  └── 过渡到下个方法（文字）

全方法对比表
学习检查点（3-4个自检问题）
下一章衔接（1句话）
```

## 五、写作风格规范

1. 代码前：1-2 句说明"这段代码做什么、为什么这样做"
2. 代码后：1 段解读输出、与 baseline 对比、说明改善了什么
3. 方法切换时：1 段过渡，格式为"方法X解决了A，但B仍存在 → 引出方法Y"
4. 语气：引导式，像在跟读者对话，不是在写 API 文档
5. 注释：只加非显而易见的注释
