## 一、设计目标

把第六章从"方法罗列"升级为"风格统一、层层递进的正式教程"。
读者读完后能回答三个问题：

1. 我的问题到底属于哪一层增强？
2. 这一层里每个方法解决什么问题？
3. 这些方法怎么选择、怎么组合、怎么评估？

---

## 二、确认的设计约束

| 约束 | 决定 |
|---|---|
| 框架 | 保留 LangChain + LlamaIndex 混用，不强制统一 |
| 先导失败案例 | 三类失败场景都要有可运行 demo |
| 代码可运行策略 | 分层处理：原理轻依赖、效果展示允许 API |
| 方法深度 | 所有方法平等对待，统一模板、统一深度 |
| LLM 模型 | 全章统一 `gpt-4o-mini` |
| Self-RAG | 降级为思想演示，不下载旧模型，用 LLM 判断方式 |
| LlamaIndex pack | 需确认兼容性，废弃则换新 API |
| 新增方法 | 流程增强加 Corrective RAG，系统增强加 Agentic RAG |

## 四、统一教学模板

每个方法按以下 8 步展开：

1. **问题场景**：这个方法解决什么问题
2. **失败案例**：基础 RAG 在这个场景下会怎样失败
3. **核心思想**：一句话 + 一段话讲清本质
4. **流程图 / 示意图**：可视化展示
5. **核心代码拆解**：3-8 行关键逻辑，去黑盒感
6. **完整可运行示例**：包含 pack 调用或完整代码
7. **效果对比**：展示增强前后差异
8. **适用场景与局限**：什么时候用、什么时候别用

### 5.2 `1. 上下文增强（重构版）.ipynb`

#### 目标
回答：**为什么检索命中了，答案还是不完整？**

#### 结构

| Cell | 内容 | 类型 |
|---|---|---|
| 1 | 标题 + 本节问题定义 | markdown |
| 2 | 统一实验设置（数据、评估函数、qna_dict） | code |
| 3 | 基础 RAG baseline（普通向量检索，作为对照） | code |
| 4-11 | 方法一：Sentence Window（按 8 步模板） | markdown + code |
| 12-19 | 方法二：Small-to-Big（按 8 步模板） | markdown + code |
| 20-27 | 方法三：AutoMerging（按 8 步模板） | markdown + code |
| 28 | 三种方法横向对比表 | markdown |
| 29 | 小结：怎么选 | markdown |
| 30 | 学习检查点 | markdown |

#### 每个方法的 8 步细节

**Sentence Window**
- 问题场景：命中句子相关但缺前后文
- 核心思想：索引时切句并记录邻居，检索时回填窗口
- 关键参数：窗口大小（前后各几句）
- 核心代码拆解：展示"切句 + 存邻居 + 检索时回填"的关键步骤
- 完整示例：保留 `download_llama_pack` 调用
- 效果对比：dataframe + 具体问题回答差异

**Small-to-Big**
- 问题场景：小块容易命中但信息不完整
- 核心思想：索引时建立小块→父块映射，检索时命中小块后回填大块
- 关键参数：父子块比例、子块大小
- 核心代码拆解：展示"建映射 + 检索小块 + 替换为父块"
- 完整示例：保留 pack 调用
- 效果对比：同上

**AutoMerging**
- 问题场景：多个相关子块分散命中
- 核心思想：索引时建父子层级，检索时按阈值自动合并
- 关键参数：合并阈值、层级深度
- 核心代码拆解：展示"建层级 + 召回叶子 + 合并判断"
- 完整示例：保留 pack 调用
- 效果对比：同上

#### 各方法要点

**迭代检索**
- 从伪代码升级为可运行代码
- 接真实 retriever + llm
- 展示两轮回答前后差异

**递归检索**
- 展示"谁拆问题、谁合并答案"
- 补一个子问题列表例子
- 可运行示例

**查询路由**
- 不再只是关键词 if-else
- 补 rule-based routing + LLM-based routing 两种方式
- 至少给 LLM-based 的可运行版本

**Corrective RAG（新增）**
- 2025-2026 年热门方法
- 核心思想：检索完先打分，不合格就换路（重写 query / 网络搜索 / 跳过）
- 流程图：检索 → 评估 → 路由（全部相关 / 部分相关 / 不相关）
- 代码建议用 LangGraph 或手写评估链
- 和 Self-RAG 对比：CRAG 是"检索后纠错"，Self-RAG 是"生成时反思"

**自适应检索 / Self-RAG**
- 补回旧版原理讲解：三环节（检索、生成、评估）
- 补回两张图：`selfrag.png` / `selftoken.jpg`
- 训练视角 vs 推理视角
- 代码不下载 LLaMA 2 模型
- 改为用 LLM 判断"是否需要继续检索"的简化演示

### 5.4 `3. 系统增强.ipynb`

#### 目标
回答：**即使流程增强做了，为什么真实系统仍然需要记忆、调度与 Agent 协作？**

#### 结构

| Cell | 内容 | 类型 |
|---|---|---|
| 1 | 标题 + 本节问题定义 | markdown |
| 2 | 场景升级：从单问答到真实系统 | markdown |
| 3 | 统一环境设置 | code |
| 4-11 | 方法一：Memory（按 8 步模板） | markdown + code |
| 12-19 | 方法二：Multi-Document Agent（按 8 步模板） | markdown + code |
| 20-27 | 方法三：Agentic RAG（按 8 步模板）⭐ 新增 | markdown + code |
| 28 | 系统增强的成本与边界 | markdown |
| 29 | 延伸阅读：Graph RAG / 多模态 RAG | markdown |
| 30 | 学习检查点 | markdown |

#### 各方法要点

**Memory**
- 补完整多轮 demo
- 链路：提问 → 读历史 → 增强检索 query → 检索 → 生成 → 写回 memory → 下一轮
- 演示两轮：建立主题 + 指代追问
- 展示无记忆 vs 有记忆差异

**Multi-Document Agent**
- 保留现有代码，但教学重排
- 按统一模板：为什么单索引失败 → 文档 agent → 顶层调度 → baseline 对比
- 统一 LLM 为 gpt-4o-mini

**Agentic RAG（新增）**
- 核心思想：Agent 自主规划检索策略，在"规划 → 检索 → 推理 → 反思"循环中动态决策
- 与前面方法的关系：集成了迭代检索（多轮）、查询路由（策略选择）、CRAG（检索评估）、记忆（上下文维护）
- 流程图：Agent 接收任务 → 规划检索策略 → 执行检索 → 评估结果 → 决定下一步（继续检索/换策略/生成回答）
- 代码建议用 LangGraph 或 LlamaIndex Agent 构建
- 展示与无 Agent 的 baseline 对比
- 适用场景：复杂多步任务、需要工具调用、需要动态策略选择

**延伸阅读**
- Graph RAG：1-2 段介绍核心思想、解决什么问题、与本章方法的关系、推荐资源
- 多模态 RAG：同上

|---|---|---|---|---|---|
| Sentence Window | 命中句子缺少前后文 | 低 | 低-中 | 优先尝试 | 上下文完整性、回答忠实性 |

| Corrective RAG | 检索结果不一定相关 | 中 | 中 | 需要检索质量保障时 | 召回准确性、回答忠实性 |
| 自适应检索 / Self-RAG | 需要动态控制检索 | 高 | 高 | 高要求场景 | 忠实性、鲁棒性 |
| 记忆 | 需要跨轮连续性 | 中 | 中 | 会话系统 | 多轮连续性、指代消解 |
| Multi-Document Agent | 跨文档协作与调度 | 高 | 高 | 复杂工程 | 跨文档正确性 |
| Agentic RAG | 需要动态策略规划 | 高 | 高 | 复杂多步任务 | 任务完成率、策略适应性 |

#### 推荐组合方案（新增）

- 组合 1：`Sentence Window + 查询路由` — 多知识源 + 上下文碎片
