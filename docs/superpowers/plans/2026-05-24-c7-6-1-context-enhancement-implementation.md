## 实验协议（前置约束）

本节所有重构必须在以下协议约束下进行：

### Baseline 配置
- 切块：字符块 256 / overlap 20
- 检索器：LangChain Chroma + bge-small-zh-v1.5，top-k=4
- 生成输入组织：`CONTEXT_CHAR_BUDGET=2500` 统一截断
- 评分入口：`simple_eval_2pt`（0/1/2 粗评）

### 题集版本
- 来源：`../3. 索引阶段/data/train_dataset.json`
- 数量：24 题（QA_INDICES = range(20) + [21, 41, 55, 30]）
- 固定方式：hard-coded indices，本节不增删

### 评分口径
- 0/1/2 粗评，由 `simple_eval_2pt` 自动判定
- tie = 分数相同
- 人工复核仅在边界 case 展示时选择性进行

### 随机性控制
- 模型温度：0.0
- 固定种子不额外设置（依赖 temperature=0）
- 重跑策略：单次运行即可，不强制多次

### 上下文预算
- 最大输入：`CONTEXT_CHAR_BUDGET=2500`
- 截断规则：`trim_context_to_budget`
- Sentence Window 窗口：WINDOW_SIZE=2
- Small-to-Big 父块：480/60，子块：100/20，最多 3 个父块
- AutoMerging 阈值：MERGE_THRESHOLD=0.10，MIN_CHILD_HITS_FOR_MERGE=2

### 方法参数
- Sentence Window：`WINDOW_SIZE=2`
- Small-to-Big：parent 480/60，child 100/20，max_parents=3
- AutoMerging：MERGE_THRESHOLD=0.10，MIN_CHILD_HITS_FOR_MERGE=2

### 可调整参数
- 允许在合理范围内调整展示用代表题（`question` 参数）
- 不允许反向修改题集、方法定义或评分逻辑来制造提分

## Task 1：重构 Notebook 开头（导航 + 问题定义 + 边界说明）

**目标**：建立清晰的教学主线和章节边界。

**步骤**：
1. 在 notebook 最开头增加"本节解决什么问题"小节：
   - baseline 往往不是完全检不到
   - 真正问题是：命中片段本身太碎、上下支撑句缺失、同段补充信息没带上
   - 本节要做的不是"再想办法检更多"，而是"把更适合生成的上下文补回来"
2. 增加"本节与其他增强层的边界"小节：
   - 这节不讲 query 改写
   - 这节不讲多轮流程控制
   - 这节不讲 agent 或系统编排
   - 这节只讲"检索命中后，如何恢复更完整上下文"
3. 将现有"统一实验设置"内容精简后移入开头，确保读者先知道"这节在干什么"

**验证**：
- 开头两段 markdown cell 能独立回答"这节解决什么问题"和"这节不解决什么问题"

## Task 3：按统一模板重构 Sentence Window 小节

**目标**：七种统一模板段落完整呈现。

**步骤**：
1. **方法直觉**：补回命中句的局部邻域，最直觉、最轻量
2. **机制解释**：索引时按句切分+记录邻居；检索时命中句查邻居映射拼上下文
3. **适用缺口**：命中句前后说明缺失、连续解释被 chunk 边界截断
4. **最小实现**：保持现有代码不变
5. **实验观察**：保持 `display_sentence_window_panel` 调用不变
6. **观察解读**：增加明确解读——"这次提分是因为补回了什么"
7. **方法小结**："什么时候值得试、什么时候不必默认开启"

**验证**：
- Sentence Window 小节包含 7 个明确段落
- 能区分"机制解释"和"实验观察"
- 有方法小结段落

## Task 4：按统一模板重构 Small-to-Big 小节

**目标**：同上。

**步骤**：
1. **方法直觉**：保留小块定位能力，但把生成上下文提升到父块
2. **机制解释**：子块写入向量库做检索，命中后映射到父块取完整上下文
3. **适用缺口**：小块定位准，但回答需要同段的条件、定义、例子
4. **最小实现**：保持现有代码不变
5. **实验观察**：保持 `display_small_to_big_panel` 调用不变
6. **观察解读**：增加解读段落
7. **方法小结**：增加小结段落

**验证**：
- 同上 Task 3

---

## Task 5：按统一模板重构 AutoMerging 小节

**目标**：同上。

**步骤**：
1. **方法直觉**：当多个证据分散命中同一父块时，按命中密度抬升到更完整父级上下文
2. **机制解释**：检索后统计每个 parent 的命中密度，超过阈值则抬升整父块
3. **适用缺口**：多个子证据共同支撑答案、同父多命中时碎片冗余
4. **最小实现**：保持现有代码不变
5. **实验观察**：保持 `display_auto_merging_panel` 调用不变
6. **观察解读**：增加解读段落
7. **方法小结**：增加小结段落

**验证**：
- 同上 Task 3

## Task 6：重构横向总结区

**目标**：结论由证据驱动，不手写漂移数字。

**步骤**：
1. 将现有的"分方法差异索引"和"同题对比总览"合并为统一的横向总结
2. 确保所有汇总数据从 `compare_df`、`summary_df` 动态生成
3. 移除任何手写固定分数的表述（如"19/48"硬编码到 prose 中）
4. 总结必须回答三个问题：
   - 三种方法分别补回了哪一类上下文
   - 它们更适合什么样的证据缺口
   - 在当前题集上，哪些结论可以由真实观察支撑，哪些只能写成边界说明
5. 方法特性对比表改为从 `summary_df` 动态渲染

**验证**：
- 总结区没有手写固定数字
- 所有统计值来自 DataFrame
- 明确区分"可观察结论"和"边界说明"
