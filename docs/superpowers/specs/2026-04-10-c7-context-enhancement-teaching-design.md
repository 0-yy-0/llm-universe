# C7 上下文增强 Notebook：教学优先设计说明

**日期**：2026-04-10  
**范围**：`notebook/C7 高级 RAG 技巧/6. 增强阶段/1. 上下文增强.ipynb`  
**成功标准（已选）**：**A — 教学优先**（读者理解机制，不强制方法在固定小题集上全面跑赢 baseline）。

## 1. 背景与问题

当前 notebook 使用 `train_dataset.json` 前若干题与 baseline / 多种增强对比。在现有 PDF 清洗与切块方式下，父块未必对应「语义段落」，保存的运行结果也未体现 Small-to-Big 等方法的优势。若仍以 **LLM 裁判通过率** 作为唯一叙事主线，会与读者观察冲突，削弱教学效果。

## 2. 目标与非目标

### 2.1 目标

- 读者能准确说明：**Baseline / Sentence Window / Small-to-Big / AutoMerging** 各自在「检索粒度」与「送入生成的上下文」上的区别。
- 读者能通过 **inspect 类输出**（或等价调试打印）看到：命中项如何被扩展为窗口或父块。
- 正文与结论 **不与未支撑的量化断言绑定**（例如「某方法通过率通常最高」）。

### 2.2 非目标（本轮）

- 不要求在本 notebook 内完成 **大规模问题扫描（mining）** 以统计显著性。
- 不要求 Small-to-Big 在固定 N 题上必须多于 baseline 的 ✅ 数量。

## 3. 题目与参考答案策略

- **教学用小问答集**：在保留与「索引阶段」数据源一致的前提下，引入 **单独维护的少量问答**（建议：独立 JSON 或 notebook 顶部显式 `DEMO_QA` 常量），满足：
  - 问题表述与 **当前索引与切块** 可检索范围对齐（可结合 `page_num` 或已知段落）。
  - 参考答案 **覆盖教学所需要点即可**，不必与原始 train 超长标答逐字一致，以降低 LLM-as-judge 的偶然 ❌ 对叙事的绑架。
- **与原有 train 的关系**：可在文中说明：全量 train 用于其他实验；本节为 **机制演示** 使用对齐后的小集。

## 4. 叙述与单元格职责

| 区块           | 职责 |
|----------------|------|
| Baseline       | 仅向量检索命中 chunk，建立对比基线。 |
| Sentence Window | 强调「句级命中 → 邻接窗口拼接」；inspect 展示窗口内容形状。 |
| Small-to-Big   | 强调「子块向量检索 → 映射父块 → 生成用父块」；inspect 展示子块与父块对应关系。 |
| AutoMerging    | 强调「多子块命中同一父块时的合并阈值行为」；与 Small-to-Big 对比表格保留。 |

- **评估表格**：保留时可明确标注为 **辅助/展示**；说明裁判规则偏严时，✅/❌ 可能无法反映「上下文是否更完整」。
- **可选短文**：1 段说明 PDF 提取 + `clean_text` 可能破坏目录与段落边界，故 **演示重点是机制**；若需强实证，见后续扩展（mining 或改进分块）。

## 5. 验收标准（教学向）

1. 读者能口头或笔记回答：四种路径在「检什么、喂什么」上的差异（可与文中对比表一致）。  
2. 读者能结合 inspect 输出解释：Small-to-Big 为何在「子块准、父块全」假设成立时有效，以及假设不成立时可能失效的原因。

## 6. 后续扩展（不在本轮必做）

- 固定管线后对更大问题集做检索失败类型标注 + 筛选「baseline 差、某增强好」的 case，用于附录或另一 notebook。  
- 按页或按章节构建父块，使 Small-to-Big 的「父块 = 语义单元」更接近真实文档结构。
