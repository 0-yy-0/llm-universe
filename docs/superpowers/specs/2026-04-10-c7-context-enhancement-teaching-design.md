# C7 上下文增强 Notebook：教学优先设计说明

**日期**：2026-04-10  
**范围**：`notebook/C7 高级 RAG 技巧/6. 增强阶段/1. 上下文增强.ipynb`  
**成功标准（已选）**：**A — 教学优先**（读者理解机制为主）；并满足 **下限**：**Sentence Window / Small-to-Big / AutoMerging 各自至少有一个示例题**，在同等评估口径下 **优于 baseline**（不必全量题集统计显著）。

## 1. 背景与问题

当前 notebook 使用 `train_dataset.json` 前若干题与 baseline / 多种增强对比。在现有 PDF 清洗与切块方式下，父块未必对应「语义段落」，保存的运行结果也未体现 Small-to-Big 等方法的优势。若仍以 **LLM 裁判通过率** 作为唯一叙事主线，会与读者观察冲突，削弱教学效果。

## 2. 目标与非目标

### 2.1 目标

- 读者能准确说明：**Baseline / Sentence Window / Small-to-Big / AutoMerging** 各自在「检索粒度」与「送入生成的上下文」上的区别。
- 读者能通过 **inspect 类输出**（或等价调试打印）看到：命中项如何被扩展为窗口或父块。
- 正文与结论 **不与未支撑的量化断言绑定**（例如「某方法通过率通常最高」）。

### 2.2 非目标（本轮）

- 不要求在本 notebook 内完成 **大规模问题扫描（mining）** 以统计显著性。
- 不要求任一方法在 **整张子集** 上的 ✅ **总数** 必须高于 baseline；但 **每种增强至少一题** 相对 baseline 更优（见 §5），实现时通过 **从 train 中挑选子集 + 必要时调整切块/检索参数** 保证可演示。

## 3. 题目与参考答案策略

- **不新增独立问答文件**：继续使用现有 `../3. 索引阶段/data/train_dataset.json`，避免多一套数据源的维护成本。
- **从已有条目中选取子集**：在 notebook 中用 **固定下标或固定 query 列表** 指向 train 内已有记录（例如由原来的「前 5 条」改为「经检索/页码核对后选出的 N 条」），选取标准写进 markdown：**与当前切块检索到的上下文可对齐**（可结合条目的 `page_num`、以及对 baseline 的一次 inspect 验证）；且 **保证每种增强各至少有一道「胜 baseline」的题**（可重复使用同一题展示多种方法，但须让读者看出差异，通常更清晰的是 **各方法至少一道专属胜场题**）。
- **参考答案**：仍用 train 中的 `answer` 字段，不在仓库里维护第二份标答；正文继续强调 LLM 裁判偏严，**不以 ✅ 数量否定机制讲解**。
- **说明句**：可注明本节是「从同一 train 集中抽子集做机制演示」，与全量评估类 notebook 区分即可。

## 4. 叙述与单元格职责

| 区块           | 职责 |
|----------------|------|
| Baseline       | 仅向量检索命中 chunk，建立对比基线。 |
| Sentence Window | 强调「句级命中 → 邻接窗口拼接」；inspect 展示窗口内容形状。 |
| Small-to-Big   | 强调「子块向量检索 → 映射父块 → 生成用父块」；inspect 展示子块与父块对应关系。 |
| AutoMerging    | 强调「多子块命中同一父块时的合并阈值行为」；与 Small-to-Big 对比表格保留；至少一道 **胜 baseline** 的标注示例。 |

- **各方法「胜场」题**：在 Sentence Window / Small-to-Big / AutoMerging 小节中，各给出至少一题，正文或表头标明该题用于展示 **相对 baseline 的改进**（满足 §5.3）。

- **评估表格**：保留时可明确标注为 **辅助/展示**；说明裁判规则偏严时，✅/❌ 可能无法反映「上下文是否更完整」。
- **可选短文**：1 段说明 PDF 提取 + `clean_text` 可能破坏目录与段落边界，故 **演示重点是机制**；若需强实证，见后续扩展（mining 或改进分块）。

## 5. 验收标准（教学向）

1. 读者能口头或笔记回答：四种路径在「检什么、喂什么」上的差异（可与文中对比表一致）。  
2. 读者能结合 inspect 输出解释：Small-to-Big 为何在「子块准、父块全」假设成立时有效，以及假设不成立时可能失效的原因。  
3. **每种上下文增强方法至少一个「胜 baseline」示例**：对 **Sentence Window、Small-to-Big、AutoMerging** 分别至少指定一道来自 `train_dataset.json` 的题目，在同一套 LLM 裁判（或文中声明的等价口径）下，该题 **增强路径的判定不劣于且至少一项严格优于** baseline（例如 baseline ❌ 而该方法 ✅，或 baseline 明显缺要点而该方法补全后判 ✅）。文中应用表格或小节标题 **显式标出**「本题用于展示某某方法相对 baseline 的收益」，避免读者觉得「一个都没解决」。

## 6. 后续扩展（不在本轮必做）

- 固定管线后对更大问题集做检索失败类型标注 + 筛选「baseline 差、某增强好」的 case，用于附录或另一 notebook。  
- 按页或按章节构建父块，使 Small-to-Big 的「父块 = 语义单元」更接近真实文档结构。
